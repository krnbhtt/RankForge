## 1. Overview & Engineering Principles

RankForge AI follows a **Contracts-First** engineering discipline. Every data shape that crosses a service boundary (Next.js web API routes, Cloud Tasks worker payloads, Gemini structured model outputs, and Firestore checkpoint documents) is strictly defined and validated using Zod schemas.

- **Zero-Tolerance Boundary Validation**: Invalid payloads are rejected at ingress before reaching application or model pipelines.
- **Typed Error Taxonomy**: All runtime exceptions conform to `AuditErrorSchema` with actionable recovery steps.
- **Deterministic Checkpointing**: Audit state transitions are serialized and recorded idempotently.

## 2. Core Domain Contracts (`@rankforge/schema`)

### 2.1 Audit Lifecycle Entities

#### `AuditStatusEnum` (Spec §6.1 Canonical 14 Statuses)
Enum representing all 14 canonical lifecycle states of an audit run:
- `'queued'`: Task received and pending worker execution.
- `'capturing'`: Target e-commerce URL is being rendered and captured by Playwright.
- `'captured'`: DOM snapshot and platform detection completed.
- `'awaiting_keyword'`: Keyword candidates resolved or awaiting explicit input.
- `'discovering'`: Top 10 organic competitors identified via Google Search Grounding.
- `'competitors'`: Competitor product storefronts being scraped in parallel.
- `'analysing'`: SEO entity deficit and CRO conversion friction audit in progress.
- `'analysed'`: Diagnostic gap synthesis complete, baseline scores checkpointed.
- `'blueprinted'`: CRO playbook and section redesign blueprint generated.
- `'rebuilding'`: Section rebuilder streaming live progressive DOM patches.
- `'verifying'`: DOM verification, layout integrity diff, and score re-calculation.
- `'complete'`: Audit finished successfully with before/after scorecards and attribution.
- `'blocked'`: Target site blocked automated capture (fallback offered).
- `'failed'`: Audit terminated with a typed `AuditError`.

#### `AuditStageEnum`

`'init' | 'scrape_target' | 'detect_platform' | 'discover_competitors' | 'crawl_competitors' | 'gap_analysis' | 'generate_patches' | 'scoring' | 'finalize'`

- `visibility`:

  - `current` (0-100): Calculated conversion score.
  - `baseline` (0-100): Pre-optimization conversion score.
  - `delta`: Score difference (`current - baseline`).
  - `breakdown`: Points for `add_to_cart` (max 25), `delivery_payment_returns` (max 20), `trust_and_proof` (max 20), `price_and_offer_clarity` (max 15), `friction_and_mobile_usability` (max 20).
- `ppi`:
  - Page Performance Index: `PPI = (Visibility * Conversion) / 100`.
  - `current`, `baseline`, `delta`.
- `attributions` (`ScoreAttribution[]`): Individual rule point allocations mapped to patch IDs.
